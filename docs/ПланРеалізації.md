| 1 | **Domain Layer + DB Schema** | Видалити старі entity та створити нові: `Episode`, `ClinicalDay`, `HourlyRecord`, `MedicalOrder`, `OrderExecution`, `FluidBalance`, `ClinicalScale`, `ScaleResult`, `MedicalNote`, `Signature`, `GeneratedPdf`, `AuditLog`, `SystemSettings`. Для всіх сутностей використовувати `UUID`, `@Version`, audit-поля. Повністю переписати `data.sql`. |
| 2 | **Repository Layer** | Переписати всі репозиторії відповідно до нової моделі даних. |

| 6 | **REST API — HourlyRecord + MedicalOrder** | Реалізувати контролери для `hourly-records/*`, `orders/*` та `executions/*`. |
| 7 | **REST API — Notes + Scales + PDF + Audit** | Реалізувати всі інші контролери відповідно до нової архітектури. |
| 8 | **Service Layer — Business Logic** | Повністю переписати бізнес-логіку сервісів: розрахунок Fluid Balance (автоматичний), клінічні шкали, підписи, генерація PDF та інші сервіси. |
| 9 | **PDF Generator** | Повністю переписати генерацію PDF відповідно до нової моделі даних. |
| 10 | **Audit Service** | Переписати та оновити сервіс аудиту. |
| 11 | **Frontend — Types + API** | Оновити всі TypeScript-типи та API-клієнт відповідно до нового REST API. |
| 12 | **Frontend — Pages** | Оновити всі сторінки застосунку відповідно до нової моделі. |
| 13 | **Frontend — Components** | Створити або переписати всі необхідні React-компоненти. |
| 14 | **Delete Old Tests** | Видалити всі існуючі тести, що належать до старої архітектури. |
| 15 | **Backend Unit Tests** | Написати нові unit-тести (`JUnit 5`) для всієї бізнес-логіки. |
| 16 | **Backend Integration Tests** | Написати інтеграційні тести (`@SpringBootTest`) для REST API та сервісів. |
| 17 | **Frontend Vitest Tests** | Повністю переписати frontend-тести на `Vitest`. |
| 18 | **Playwright E2E Tests** | Створити повний набір E2E-тестів заново. |
| 19 | **CI/CD + Documentation** | Оновити GitHub Actions, `README.md`, `AGENTS.md` та іншу технічну документацію. |
