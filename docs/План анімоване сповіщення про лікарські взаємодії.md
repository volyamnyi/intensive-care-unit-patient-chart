# План реалізації: анімоване сповіщення про лікарські взаємодії

**Модуль:** Листок лікарських призначень
**Статус:** Заплановано, реалізація не розпочата
**Пов'язані задачі:** № 304 (виявлення взаємодій — закрито), № 350, № 351, № 352, № 353, № 354, № 355 (фази реалізації)
**Дата складання:** 7 жовтня 2026 року

---

## 1. Мета

Спроєктувати та реалізувати механізм користувацького інтерфейсу, який виявляє лікарські взаємодії безпосередньо в листку лікарських призначень та наочно повідомляє про них користувача.

Сповіщення повинно:

- відображатися в контексті конкретних лікарських призначень;
- однозначно показувати ступінь небезпечності взаємодії;
- містити короткий інформативний опис наслідку взаємодії;
- використовувати колір, текст та іконографіку одночасно;
- мати плавну анімацію появи;
- виїжджати з лівої частини області інтерфейсу;
- не блокувати роботу з листком для взаємодій, які не потребують негайного блокування;
- бути доступним для клавіатури та програм читання з екрана;
- коректно працювати при одночасному виявленні декількох взаємодій.

---

## 2. Вихідна точка

Механізм виявлення взаємодій вже існує (задача № 304, закрита):

- Серверна служба обчислює взаємодії за запланованим періодом призначення.
- Небезпечними вважаються рівні: середній, високий, критичний. Низький рівень зберігається в базі даних, але попереджень не створює.
- Інтерфейс отримання даних: запит `GET /api/prescriptions/{listId}/interactions`.
- Сторінка деталей листка перезапитує взаємодії після кожної зміни (додавання, планування, скасування, зміна дат).
- Поточне візуальне оформлення: миготіння назви препарату, червона рамка на клітинках перетину дат, спливна підказка з переліком пар.

Цей план не змінює серверну частину. Змінюється лише рівень представлення: замість нескінченного миготіння — контекстне стійке сповіщення з одноразовою анімацією появи.

---

## 3. Чому не спливне повідомлення

Звичайне короткочасне спливне повідомлення (toast, snackbar) для цього сценарію не підходить:

- інформація про взаємодію не є результатом звичайної операції користувача;
- вона безпосередньо пов'язана з конкретними рядками призначень;
- вона може мати клінічно значущий наслідок;
- вона повинна залишатися доступною для повторного прочитання, а не зникати автоматично.

Тому обране рішення: **контекстне стійке сповіщення**, прив'язане до конкретної групи взаємодіючих призначень.

---

## 4. Три рівні сповіщення одночасно

Користувач отримує відповідь на чотири питання одразу — **де, що, наскільки небезпечно, чому**:

1. **Локальне виділення** — відповідні рядки призначень отримують оформлення рівня небезпеки.
2. **Анімоване контекстне сповіщення** — картка з рівнем, назвами препаратів та описом.
3. **Агрегований індикатор** — якщо взаємодій декілька, головне сповіщення показує найвищий рівень та кількість.

---

## 5. Конфігурація рівнів небезпеки

Існує єдина конфігурація рівнів, спільна для сповіщення та таблиці. Жодних розкиданих по коду кольорів та міток.

| Рівень | Пріоритет | Мітка українською | Колір | Іконка | Семантика доступності |
|---|---|---|---|---|---|
| Критичний (`critical`) | 4 | критично | Червоний (системний деструктивний) | Восьмикутник уваги | Перериваюче сповіщення, оголошується одразу |
| Високий (`high`) | 3 | високо | Помаранчевий | Трикутник уваги | Статусне повідомлення |
| Помірний (`medium`) | 2 | помірно | Бурштиновий (жовтий) | Коло уваги | Статусне повідомлення |
| Низький (`low`) | 1 | низько | Нейтральний сірий (не зелений) | Інформаційна іконка | Тільки конфігурація, не відображається |

Правила:

- Колір ніколи не є єдиним носієм значення. Кожен стан має одночасно колір, іконку, текстову мітку та програмну семантику.
- Зелений колір для низького рівня не використовується: у контексті призначень зелений зчитується як «безпечно, схвалено», що вводитиме в оману.
- Низький рівень описаний у конфігурації про запас (якщо сервер колись почне його надсилати), але сьогодні не відображається. Низькі взаємодії видно в адміністративному перегляді «Зміст бази».
- Критичний рівень — окремий четвертий рівень, а не згорнутий у високий: сервер уже обчислює та повертає цю відмінність, втрачати її немає підстав.

---

## 6. Виділення рядків таблиці

При виявленні взаємодії відповідні рядки препаратів отримують оформлення рівня:

- світле фонове тонування відповідного кольору;
- чітка кольорова межа або індикатор зліва;
- іконка рівня біля назви;
- текстова мітка рівня.

Обмеження:

- Заборонено заливати весь рядок насиченим червоним, жовтим або зеленим, якщо це погіршує читабельність тексту та дат.
- Існуючі кольори статусів доз (заплановано, виконано, скасовано) завжди мають перевагу: попередження додає оформлення, а не замінює заливку.
- Межа клітинок перетину дат зберігається, але фарбується за рівнем пари (критичний — червоний, високий — помаранчевий, помірний — темно-жовтий), замість єдиного червоного для всіх.
- Контрастність тексту — не нижче вимог доступності; кільця фокусу — повної непрозорості.

---

## 7. Компонент сповіщення

Окремий повторновикористовуваний компонент, умовна назва — `MedicationInteractionAlert`. Складається з:

1. Індикатора рівня небезпеки.
2. Іконки.
3. Короткого заголовка.
4. Короткого опису взаємодії.
5. Назв препаратів, між якими виявлено взаємодію.
6. За потреби — розгортання деталей.
7. Механізму згортання (закриття дозволене лише там, де це дозволяє рівень: високий рівень не ховається взагалі).

Приклад для високого рівня:

```text
┌─────────────────────────────────────────────┐
│ Значок уваги  НЕБЕЗПЕЧНА ВЗАЄМОДІЯ         │
│                                             │
│ Моксифлоксацин + Кеторолак                  │
│ Виявлено взаємодію високого ступеня.        │
│ Ризик розвитку небажаної реакції.           │
└─────────────────────────────────────────────┘
```

Приклад для помірного рівня:

```text
┌─────────────────────────────────────────────┐
│ Значок уваги  ПОМІРНА ВЗАЄМОДІЯ            │
│                                             │
│ Омепразол + Клопідогрель                    │
│ Ефективність клопідогрелю може знижуватися.│
└─────────────────────────────────────────────┘
```

Текст повідомлення формується зі структурованих даних взаємодії (рівень, назви препаратів, опис, дати перетину), а не вигадується компонентом. Формат:

```text
[Рівень небезпеки]

[Препарат А + Препарат Б]

[Короткий опис клінічно значущої взаємодії]
```

## 8. Анімація появи

При появі взаємодії компонент:

1. Починає поза лівою межею своєї області (зсув на 16 пікселів вліво, прозорість нульова).
2. Плавно переміщується у фінальну позицію з одночасним проявленням (тривалість 250 мілісекунд, плавна крива без різкого виходу за межі).
3. Залишається у стабільному стані.

Заборонено: нескінченне миготіння, пульсація, трясіння, підстрибування, еластичні ефекти — особливо для червоного стану високої небезпеки. Анімація привертає увагу один раз, після чого компонент стабільний.

Повторна анімація запускається лише якщо з'явилася нова взаємодія, змінився рівень, змінилися препарати або взаємодія була видалена та виявлена знову. Звичайне перерендерування сторінки (наприклад, редагування дози) анімацію не перезапускає. Визначення «той самий набір взаємодій» — стабільний хеш набору (ідентифікатори пар, рівні, дати перетину).

### Режим зменшеного руху

Обов'язковий альтернативний режим через медіа-запит `prefers-reduced-motion`:

- рух вимкнено повністю;
- сповіщення з'являється одразу у фінальному вигляді;
- рівень, колір, іконка та текст видно без втрат.

Користувач цього режиму не втрачає інформацію — втрачається лише декоративний рух.

---

## 9. Прив'язка до конкретної взаємодії

Заборонено показувати знеособлене «Виявлено взаємодії!» у верхній частині сторінки без пояснення, до яких препаратів воно відноситься. Компонент завжди контекстний: назви обох препаратів, рівень та опис — в одному блоці.

Сповіщення розміщується в потоці сторінки між попередженням про відсутній код класифікації та таблицею призначень. Воно займає окрему область на всю ширину колонки, не перекриває таблицю, не використовує спливні шари поверх дат та призначень. При відсутності взаємодій місце не резервується — таблиця піднімається вгору.

---

## 10. Декілька взаємодій одночасно

Усі проблемні рядки виділяються своїми рівнями. Сповіщення агрегуються:

- головне сповіщення показує найвищий рівень та кількість, наприклад: «Виявлено взаємодій: 3. Найвищий рівень — високий»;
- користувач розгортає повний перелік, відсортований за спаданням рівня;
- правило пріоритету: критичний (4) вище високого (3), високий вище помірного (2), помірний вище низького (1);
- максимум визначає головне сповіщення, тож на екрані ніколи немає кількох конкуруючих «головних» повідомлень.

Розгортання за замовчуванням: розгорнуто, якщо найвищий рівень високий або критичний; згорнуто, якщо лише помірні. Вибір користувача зберігається на час сесії перегляду листка.

---

## 11. Поведінка за рівнями

**Високий та критичний рівень:** червоний (критичний) або помаранчевий (високий) стиль, чіткий заголовок, назви препаратів, короткий опис. Автоматичного зникнення немає, приховати повідомлення таймером не можна, після появи табличний індикатор лишається. Модальне блокування всього листка не застосовується.

**Помірний рівень:** жовто-бурштиновий стиль, заголовок «Помірна взаємодія», назви препаратів, короткий опис, виділення рядків. Сповіщення лишається доступним, доки існує взаємодія. Допустиме згортання.

**Низький рівень:** сьогодні не відображається (сервер таких попереджень не надсилає). Описаний у конфігурації нейтрально-сірим про запас.

---

## 12. Життєвий цикл

| Подія | Реакція інтерфейсу |
|---|---|
| Виявлено нову взаємодію | Одноразова анімація появи, голосне оголошення для читача з екрана |
| Підвищення рівня (наприклад, з помірного до високого) | Одноразова повторна анімація, голосне оголошення про підвищення |
| Зміна без підвищення (додано пару того ж рівня, змінено дати або текст, зниження рівня) | Вміст оновлюється на місці без анімації, спокійне оголошення або тиша |
| Звичайне оновлення даних без змін взаємодій | Нічого: той самий вузол, без повторної анімації, без звернень до читача з екрана |
| Препарат видалено, взаємодія зникла | Сповіщення та підсвічування прибираються, застарілих повідомлень не лишається |
| Помилка отримання даних | Зберігається попередній стан, сторінка не блокується |

Додавання препарату: сповіщення з'являється лише після завершення актуалізації даних, а не на проміжних станах форми. Видалення препарату: прибираються і сповіщення, і підсвічування, і застаріле повідомлення доступності.

---

## 13. Доступність

- Звичайне повідомлення має семантичну роль статусу; термінове повідомлення високого або критичного рівня — роль тривоги. Роль тривоги застосовується ощадливо: лише перше виявлення та підвищення рівня, інакше читач з екрана перериватиметься на кожному редагуванні дат.
- Користувач клавіатури може перейти до сповіщення, розгорнути деталі, виконати доступну дію, згорнути, якщо дозволено рівнем.
- Читач з екрана отримує щонайменше: рівень словами, назви обох препаратів, опис, період перетину дат.
- Колір ніколи не єдиний носій значення: завжди поруч іконка та текстова мітка.
- Контрастність тексту — не нижче 4.5 до 1, міток — не нижче 3 до 1.
- Підтримуються: зменшений рух, масштабування 200 відсотків, вузький вікно перегляду 360 пікселів, примусові системні кольори.
- Цілі дотику на сенсорних екранах — не менше 44 пікселів за висотою.

---

## 14. Адаптивність

- **Настільний комп'ютер (ширше 1024 пікселів):** сповіщення на всю ширину колонки над таблицею; перелік з трьох і більше пар — у дві колонки.
- **Планшет (640–1024 пікселі):** компактніше (менший текст та мітки, перелік в одну колонку); підсвічування групи конфлікту працює дотиком та фокусом так само, як наведенням миші.
- **Вузький екран (вужче 640 пікселів):** картка на всю ширину, вміст стеком (іконка та заголовок, назви, опис, дати, кнопка); горизонтальної прокрутки не додається.

---

## 15. Розділення даних та представлення

Компонент не прив'язується до конкретного тексту або кольору напряму. Логіка обчислення визначає лише рівень (середній, високий, критичний), а представлення (колір, іконка, заголовок, пріоритет, семантика доступності) береться з єдиної конфігурації рівнів.

Модель представлення містить: ідентифікатор взаємодії, ідентифікатори та назви препаратів, рівень, заголовок, опис, пріоритет, стан видимості, мітку доступності.

---

## 16. Тестування

**Модульні тести:** відповідність рівнів оформленню (високий, помірний, низький), порядок пріоритетів, дедуплікація двонаправлених пар, стабільність підпису набору, поведінка при невідомому рівні.

**Компонентні тести:** відображення сповіщення, коректні назви, опис, іконка, рівень, кольори, декілька взаємодій, агрегація, розгортання та згортання, видалення, зміна рівня.

**Тести анімації:** початковий прихований стан, старт переходу, фінальний видимий стан, відсутність повторної анімації при звичайному перерендеруванні, анімація при новій взаємодії, вимкнений рух у режимі зменшеного руху.

**Тести доступності:** ролі статусу та тривоги, мітки доступності, живі області, клавіатура, фокус, контрастність.

**Наскрізні тести (Playwright):** сценарії високого, помірного та низького рівнів; декілька взаємодій одночасно (одне агреговане сповіщення, усі рядки підсвічені); видалення препарату (сповіщення та підсвічування зникають); режим зменшеного руху (руху немає, сповіщення є).

**Візуальні регресійні тести:** знімки сповіщення для високого, помірного та низького рівнів, декількох взаємодій, вузького вікна, розгорнутого стану, стану зменшеного руху.

## 17. Фази реалізації

|---|---|---|

## 18. Рішення, що очікують підтвердження власника

1. **Четвертий рівень «критичний»** (за замовчуванням — так): окремий червоний рівень з пріоритетом 4, оскільки сервер уже обчислює та повертає цю відмінність. Альтернатива — згорнути критичний у високий (не рекомендовано, втрачається клінічна інформація).
2. **Голосні оголошення** (за замовчуванням — при першому виявленні та при підвищенні рівня): роль тривоги лише для цих двох переходів, решта — спокійні статуси або тиша. Альтернатива — роль тривоги лише для критичного рівня.
3. **Низький рівень сірим і не відображається** (за замовчуванням — так): зелений відхилено, бо в контексті призначень він зчитується як «безпечно». Альтернатива — показувати низькі згорнутими.
4. **Структура файлів** (за замовчуванням — компонент сповіщення, модель виведення, хук сигналу): чиста модель виведення зі стабільним підписом набору як єдиний тригер анімації.
5. **Політика розгортання** (за замовчуванням — розгорнуто при високому або критичному, згорнуто при лише помірних).
6. **Приховування** (за замовчуванням — лише згортання на час перегляду, без збереження між сесіями; високий рівень не ховається взагалі).
7. **Формат дат перетину** (за замовчуванням — короткий день та місяць, наприклад 10.09–15.09).
8. **Базові знімки екрана** (за замовчуванням — закоммітити нові, ASCII-макети як тимчасовий орієнтир).

## 19. Критерії прийняття

Реалізацію вважати завершеною лише якщо виконано всі пункти:

- [ ] взаємодія визначається існуючим механізмом виявлення;
- [ ] інтерфейс отримує актуальний список взаємодій;
- [ ] підтримуються високий, помірний та низький рівні (низький — конфігураційно);
- [ ] високий рівень має червоне представлення;
- [ ] помірний рівень має жовте представлення;
- [ ] низький рівень має нейтральне представлення;
- [ ] колір не є єдиним індикатором рівня;
- [ ] відповідні рядки призначень підсвічуються;
- [ ] відображаються назви взаємодіючих препаратів;
- [ ] відображається короткий опис;
- [ ] сповіщення плавно з'являється;
- [ ] сповіщення виїжджає з лівої частини;
- [ ] немає нескінченного миготіння та пульсації;
- [ ] сповіщення високого рівня не зникає автоматично;
- [ ] декілька взаємодій агрегуються в одне;
- [ ] найвищий рівень має пріоритет;
- [ ] повторне перерендерування не запускає анімацію повторно;
- [ ] нова взаємодія запускає анімацію;
- [ ] видалення препарату видаляє відповідне попередження;
- [ ] зміна рівня коректно оновлює інтерфейс;
- [ ] сповіщення не перекриває критичні дані таблиці;
- [ ] адаптивна верстка реалізована;
- [ ] режим зменшеного руху підтримується;
- [ ] доступність з клавіатури реалізована;
- [ ] семантика для читачів з екрана реалізована;
- [ ] модульні тести додані;
- [ ] компонентні тести додані;
- [ ] наскрізні тести Playwright додані;
- [ ] візуальні регресійні тести додані;
- [ ] існуючі тести не регресували.
