## 1. Стратегія тестування

### 1.1 CI-only (обов'язково)

Усі тести виконуються виключно через GitHub Actions (`format-check`, `backend-test`, `backend-integration`, `frontend-test`, `e2e-test`, `build`). Локальний запуск тестів заборонений (AGENTS.md). Локально дозволені лише pre-flight перевірки: `mvn compile`, `npm run lint`, `npx tsc --noEmit`, `npm run build` — без запуску тестових раннерів.

Робочий цикл кожної фази: реалізація → commit → push → CI → тriage артефактів (`gh run download` → `playwright-test-results`, `playwright-report`, `vitest-coverage`, `backend-test-results`).

### 1.2 Рівні тестів — де що живе

| Рівень | Раннер / CI job | Що тестуємо | Що НЕ тестуємо |
|---|---|---|---|
| **Frontend unit** | Vitest (jsdom), `frontend-test` | Пропси, стани, edge cases компонентів: `HourlyGridDialog`, `HourlyGrid`, `IntensiveCareCard`, `criticalRanges`; моковані axios endpoints, `matchMedia`, fake timers | Розмітку/позиціонування sticky, реальну анімацію, фокус-пастку в реальному браузері (обмеження jsdom) |
| **Backend unit** | JUnit, `backend-test` | Сервісний шар: optimistic-locking 409 (`HourlyRecordServiceTest` — існуючий), валідація | UI-поведінку |
| **Backend integration** | JUnit `-Pintegration-test` (PostgreSQL 16), `backend-integration` | HTTP-контракти: PATCH `/hourly-records/{id}` зі stale version → 409 + `ErrorResponse` | — |
| **Playwright E2E** | `e2e-test` (chromium, 40 хв, 7 проєктів, `fullyParallel`, 2 retries) | Повний користувацький шлях у браузері: відкриття/закриття модального вікна, редагування, клавіатура, sticky-панелі, друк, 409, undo | Все, що можна довести юніт-тестом (піраміда) |

Правило піраміди: підсвітка критичних значень, плюралізація, статусні лейбли, версійна логіка — юніт-тести; відкриття діалогу, фокус, скрол, друк, конкурентність — E2E. Один E2E-кейс повинен мати обґрунтування «чому не юніт».

### 1.3 Ізоляція тестових даних (E2E)

- **Епізод на spec-файл** (без `.first()` на спільних даних):
  - `a1111111` (Петренко) — зайнятий: `signoff`, `signoff-full-chain` (підписують `b1111111` + `b1111112`) — **не чіпаємо**.
  - `a2222222` (Коваленко) — **новий «господар» модального вікна**: `b2222222` (Доба 2, OPEN — редагування), `b4444444` (Доба 1, NURSE_SIGNED — locked-перегляд). Тут живуть `tests/specs/nurse/modal-grid.spec.ts` і `tests/specs/doctor/modal-therapy.spec.ts`.
  - `a3333333` (Сидоренко) — зайнятий: vitals, prescriptions, notes, scales, order-execution — **не чіпаємо**.
- **Ізоляція на рівні години**: на `b2222222` seed-записи лише в години 0 та 2 (`c2222001`, `c2222002`). Нові spec-файли пишуть/читають годину **4:00** (`Сеча 4:00`) та «майбутні» години (поточний час + 1h, патерн `planHour` з `order-execution.spec.ts`), щоб не конфліктувати між собою та з ретраями.
- **Ідемпотентність при CI-retries=2**: перед записом у клітинку терапії перевіряємо стан (`✓`/`✕` зайнято → беремо наступну годину); undo-тести самі відновлюють значення.
- **Дублікати `aria-label`**: інлайн- і модальна таблиці мають однакові `aria-label="Сеча 4:00"`. Усі E2E-запити після відкриття діалогу обмежуються `getByRole('dialog')`-контекстом. У #137 перевірити, чи base-ui ховає фон (`inert`/`aria-hidden`) — якщо так, Playwright строгий режим вирішує запити сам; якщо ні — фіксуємо це як обов'язкову конвенцію (див. §5.6).

### 3.3 #136 — Morph open/close animation + reduced motion

Фаза чисто CSS/вимірювальна; jsdom не відтворює анімацію. Покриття:

#### Unit (Vitest) — опційний smoke

| Кейс | Кроки | Очікування |
|---|---|---|

- [ ] **Початковий фокус** — кнопка закриття (✕) у шапці; один Tab → перша порожня клітинка поточної години (unit N: `activeElement`).
- [ ] **Повернення фокусу** на тригер при будь-якому шляху закриття: Esc / ✕ / «Назад до карти» (E2E N4/N5).
- [ ] **`aria-modal="true"` + `role="dialog"`** — присутні на popup (E2E: `toHaveAttribute`), `aria-labelledby` резолвиться на sr-only DialogTitle (accessible name).
- [ ] **Focus trap** — Tab-цикл не виходить за межі діалогу; перевірка поведінки FocusGuards після Enter-blur, коли фокус опиняється на `body` (E2E: 12× Tab у циклі; unit: best-effort).
- [ ] **Escape з `isTopmost`** — вкладені Select/Tooltip закриваються першими; другий Esc закриває діалог (E2E: відкрити Select у діалозі → Esc → Select закритий, діалог відкритий → Esc → діалог закритий).
- [ ] **Live region `role="status"` (polite)** — без оголошень при завантаженні; оголошення лише за подіями користувача.
- [ ] **`isComposing` guard** у `Cell.onKeyDown` (IME-безпека Enter).
- [ ] **Скидання чернетки при закритті** — blur `document.activeElement` перед розмонтуванням; E2E N-чернетка+Esc комітить.
- [ ] **Дубльовані `aria-label`** — стратегія: scoping `getByRole('dialog')`; перевірка `aria-hidden`/`inert` фону base-ui (зафіксувати результат у цьому плані §5.6).
- [ ] **Focus rings** — повна непрозорість `ring-ring` + `ring-offset-card`; кнопка закриття включно (перевірка класів юнітом + скріншот при розборі).
- [ ] **reduced-motion** — функціональність (фокус, aria) не залежить від анімації (E2E).

### 4.2 #138 — Edge cases

- [ ] **409**: чернетка користувача збережена (стирається лише поза фокусом); банер «Запис змінено іншим користувачем» неблокуючий; «Оновити дані» → `onRefresh` + ресинк `recByHour`/`localRecordMap`; «Залишити мій варіант» → retry з новою версією; жодного тихого перезапису.
- [ ] **Locked day live**: `isLocked` оновлюється в модальній таблиці (`readOnly`), форма призначень прихована, тонкий банер `Lock` «Доба підписана — перегляд»; дані не затемнюються (read-only ≠ hidden).
- [ ] **Print**: `print:hidden` на popup; portal-контейнер не переживає `@media print` (E2E print-emulation).
- [ ] **Rapid toggle**: тригер недоступний, поки вікно відкрите; захист `onOpenChange`; keyframes покривають `[data-closed]` (popup змонтований під час exit-анімації) — 10× цикл без завислого фокусу, без втрати чернеток, без порожнього popup.
- [ ] **`dayLoading`**: спінер у панелі інструментів діалогу без page-level оверлея.
- [ ] **1366×768 / zoom 200% / safe-area**: внутрішній скрол без поломки розмітки (E2E viewport; zoom/safe-area — ручна перевірка + скріншоти при розборі).
- [ ] **Mobile <1200px**: `isMobile` → touch-рядки 44px, sticky-колонка вимкнена, рейл прихований (unit: `isMobile` пропс; E2E viewport 375×667 за бажанням).

### 4.3 #139 — Outlier rail / alarm chip / status strip

- [ ] Рейл і підсвітка клітинок читають **той самий** `CRITICAL_RANGES` (`criticalRanges.ts`) — юніт «єдине джерело правди».
- [ ] Heat-шкала рейла: нейтральний → янтарний → червоний за кількістю порушень; штрихування — година неповна; клік по рейлу скролить до години.
- [ ] Чіп: лише при `n>0`; `{n} критичне/критичні/критичних значень` (1 / 2–4 / 5+); `aria-label="Показати перше критичне значення"`; клік → `scrollIntoView` + фокус на першу критичну клітинку (показники → втрати).
- [ ] Лічильник «Заповнено X/24 год» — коректний після введення/оновлення (E2E N14).
- [ ] Статус: «Зберігається…» / «Збережено» / «Помилка»; успіх `text-[#2E7D32]` / `dark:text-[#81C784]`; пер-клітинковий зелений спалах 300 мс (патерн спінера `TherapyCell`) — юніт з fake timers.
- [ ] Годинник + акцент поточної години 2px з `realClockHour`.
- [ ] **Без звуку, без миготіння, без анімації** в рейлі/чіпі (alarm fatigue, NPSG.06.01.01) — E2E-перевірка відсутності CSS-анімацій.

### 4.4 #140 — Undo

- [ ] Сесійний журнал (~20 записів) фіксує `{hour, key, prevValue, newValue, version}` на кожен коміт `saveCell`.
- [ ] «↩ Скасувати останню зміну» (футер) відкочує патчем `prevValue` зі збереженою версією; **недоступна на заблокованій добі** + tooltip пояснення.
- [ ] `Ctrl+Z` у сфокусованій клітинці → чернетка до останнього збереженого, без запиту; Esc у забрудненій → revert; другий Esc → закрити.
- [ ] Toast-undo: «Виконання скасовано · [Скасувати]», позиція `absolute bottom-16`, `aria-live="polite"`, авто-зникнення (3 с дія / 5 с toast) — fake timers.
- [ ] Без блокування виходу за межі: значення завжди комітяться, позначаються червоним ring + polite-повідомлення + audit trail.
- [ ] Без стеків модальних вікон: конфлікти/undo — інлайн-банери та toasts.

## 5. Ризики та флейковість

### 5.1 Таймери (годинник 30 с, autosave 2 с, статус idle 3 с)

- **Юніт:** `vi.useFakeTimers()` — годинник `advanceTimersByTime(30_000)`; `useAutoSave` статуси через таймери; toast 3 с/5 с.
- **E2E:** ніколи не асертимо конкретний час годинника — лише формат `/^\d{2}:\d{2}$/`; статусні лейбли перевіряємо з дефолтним auto-wait. Коміт клітинок у E2E — через Enter/blur (миттєвий `saveCell`), а не через 2-секундний autosave (він для нотаток).
- **Флейк-сигнал:** «passed on retry» із таймаутом на статусному лейблі = гонка з `useAutoSave` — фіксувати через `waitForResponse`, а не очікування тексту.

### 5.2 Tooltip затримки

`TooltipProvider` у `IntensiveCareCard` має `delay=0`, але base-ui додає власну затримку появи. E2E: після `hover` використовувати `await expect(page.getByText('На весь екран (Alt+Enter)')).toBeVisible()` з дефолтним таймаутом; ніколи не асертити «tooltip відсутній» одразу після hover (гонка). Tooltip на шапці («Двічі клацніть, щоб розгорнути») — hover + очікування перед `dblclick`.

### 5.3 Анімації (#136)

- Закриття має exit-анімацію (~150 мс, `[data-closed]`) — після Esc завжди `await expect(dialog).toBeHidden()` (auto-retry), не `toBeVisible`-інверсії та не фіксовані паузи.
- Відкриття — `expect(dialog).toBeVisible()` (auto-wait перекриває 150–200 мс).
- «Клік по підкладці не закриває»: оскільки popup `inset:0`, клік завжди потрапляє на popup — тест клікає нейтральну зону (заголовок шапки).
- Ретраї в CI (2) — інструмент вимірювання, не лікування: тест, що потребує ретраїв через анімацію, = флейк, root-cause до #136.

### 5.4 Друк

`page.emulateMedia({ media: 'print' })` застосовується до контексту сторінки; обов'язково `emulateMedia({ media: 'screen' })` у `finally`/після кейсу (або окремий тест зі свіжим `goto`), інакше наступні тести в spec побачать print-режим. Діалог у print — `toHaveCount(0)` або hidden.

### 5.5 Дві копії grid (inline + dialog) — ризик розбіжності стану

- Єдине джерело правди — `gridProps` у `IntensiveCareCard`; обидві копії отримують той самий об'єкт пропсів. Юніт: після редагування в діалозі інлайн-клітинка оновлюється після `onRefresh` (mock records + rerender).
- E2E: усі запити після відкриття — через `dialog.getBy*`; перевірка інлайн-таблиці — після закриття.
- Якщо base-ui **не** ховає фон (`aria-hidden`/`inert`): дубльовані `aria-label` ламають строгий режим Playwright — документуємо і не використовуємо page-level `getByLabel` для клітинок, коли діалог відкритий (це і є причина, чому N6 в #141 фіксує поведінку).

### 5.6 Спільні seed-дані та паралельність

`fullyParallel: true` + 2 retries: кожен spec — на своєму епізоді; години-«власники» (4:00, «майбутні» години) уникнути перезапису чужих записів; патерн «пропустити зайняту клітинку» (з `order-execution.spec.ts`) для терапії. Тести-редагування не підписують діб (підпис — лише в `signoff`-спеках на `a1111111`).

### 5.7 Селектори, що виживають рефакторинг

Пріоритет: `getByRole('dialog')` → `getByRole('button', { name })` / `getByLabel` → `filter({ hasText })` на рядках → `data-slot` (лише для скрол-контейнера). Жодних CSS-ланцюжків типу `div > div > table > tbody > tr:nth-child(3)` (виняток — існуючий патерн `cellAtHour` у юнітах, де це допустимо).
